# Documentation Review Criteria

Use this reference when the review target is primarily documentation.

Rate across these dimensions:

- Substance: Does it cover what readers actually need?
- Packaging: Is the structure logical and easy to navigate?
- Accuracy: Is it factually correct and current?
- Effectiveness: Does it help the intended audience succeed?
- Clarity: Is it understandable and unambiguous?
- Quality: Overall professionalism, polish, and consistency

## Review Notes

- Prefer pointing to concrete omissions, confusing sections, or stale claims.
- Distinguish weak writing from missing content; they are different problems.
- Check whether examples, commands, and filenames still match the repo.
